Safety model

What protects your host, and what is your responsibility.

No authentication, by design. Chege Agent is a single-user local service. Anyone who can reach port 8001 has full API access. Keep the loopback binding (CHEGE_HOST=127.0.0.1); use an SSH tunnel for remote access and never publish the port to the public internet. Tool availability is governed by the enable/disable and grant rules below.

Layers of protection

Network boundary

Compose publishes only 127.0.0.1:8001 on the host; Postgres has no host port at all. The API is reachable at http://127.0.0.1:8001/.

Path containment

Every file target is canonicalised and rejected if it escapes workdir/{project} (traversal, symlinks, absolute paths, NUL bytes).

Approval gates

auto_edit (the default) permits ordinary writes and an exact allowlist of shell-free commands (pytest, git status, …). Deletes, commits, process kills, network and other shell commands require confirmation. ask_all asks before every tool, and full_auto skips risk-based prompts — but neither can bypass tool governance below.

Tool governance Shipped

Every tool has an enabled flag and a grant_mode (none or prompt_once). Disabled tools are removed from the tool schemas sent to the model and blocked again at execution time — a text-protocol tool-call injection cannot bypass disabling. prompt_once asks you for a grant once per run before that tool executes; grants are recorded in the tool_grants table for auditing. Governance is checked before the approval policy, so disabled tools always block and grants are required even under full_auto. Names and descriptions shown in the UI come from trusted server-side metadata, never model output. Manage tools on the Tools page.

Sandbox backend

The Docker backend is intended to use the restricted socket proxy (tecnativa/docker-socket-proxy) and a per-project container. If you run with --local-sandbox, there is no process isolation — treat the agent as trusted code.

Automatic checkpoints

Each run snapshots the workspace first; revert saves dirty work to a safety stash before restoring, so unrelated edits are not lost.

Activity feed

Raw server logs are not exposed. The playground Activity tab shows ordered, structured and redacted event summaries (phases, start, completion and tool events) instead.
