Setup & configuration

One command on a fresh instance; sane defaults for a personal app.

Looking to change defaults? Use the Settings console for providers, context budget, agent limits and theme (every control has a plain-language tooltip). Tool enable/disable and grants live at /tools. This page is the deployment guide and .env reference.

Deploy

git clone <your-repo-url> && cd "Chege Agent"
bash scripts/deploy.sh --isolated

This recreates only chege-agent-local-web; it never touches unrelated containers. The script syncs .env, validates compose, builds, waits for health, and prints loopback URLs plus SSH-tunnel instructions. Open the canonical local URL http://127.0.0.1:8001/. The API is bound to 127.0.0.1 and is not published on 0.0.0.0.

Other Docker stacks already running? Set CHEGE_PORT to a free port in .env and keep using bash scripts/deploy.sh --isolated: unique container names and a private network, with no orphan removal of existing apps.

Providers

The Settings provider picker lists llama_cpp (llama.cpp), ollama (Ollama) and named cloud providers — openai, deepseek, gemini, grok, anthropic, mistral, groq, openrouter, together, perplexity and custom — based on default_provider. Each cloud provider keeps its own endpoint, default model and masked token under provider_configs. Only the selected runner is used; the playground can still override the provider per run.

llama.cpp (llama_cpp, default): llamacpp_url (http://host.docker.internal:8080/v1), llamacpp_model and llamacpp_ctx (8192).

Ollama (ollama): ollama_url (http://host.docker.internal:11434), ollama_model, ollama_num_ctx (8192) and ollama_keep_alive.

Cloud providers: each has a vendor default endpoint (for example https://api.deepseek.com/v1 or https://generativelanguage.googleapis.com/v1beta/openai), a default model and its own token. Tokens are saved per provider in data/settings.json, masked in API responses, and can also come from CHEGE_<PROVIDER>_API_KEY. The legacy openai_base_url / openai_api_key / openai_max_tokens fields remain as fallbacks for the openai profile.

llama-server knobs — llamacpp_ctx, llamacpp_model, host/port and n_gpu_layers — take effect on the host only after bash scripts/llamacpp.sh restart. The Settings UI marks which controls need a restart; other settings apply to the next run or immediately.

Settings persistence

PATCH /api/v1/settings — applies changes to the running process only; cleared on restart.

PUT /api/v1/settings/defaults — the Settings UI's Save as defaults; applies changes and persists them to data/settings.json (atomic write, mode 0600).

DELETE /api/v1/settings/defaults — clears saved defaults; runtime values remain until restart.

GET /api/v1/settings returns the masked current settings. Appearance/theme is stored only in the browser (localStorage key lte-theme) and is never sent to the server.

Settings fields (with tooltips)

Every control in /settings has a plain-language tooltip — hover to read it (25 tooltips in total). The fields you can edit are:

  • default_provider — llama_cpp / ollama / any cloud provider id
  • default_temperature (0.2)
  • default_top_p (0.9)
  • default_context_window (8192)
  • max_steps (50)
  • run_timeout_seconds (600)
  • provider_timeout_seconds (120)
  • sandbox_backend — read-only, docker
  • llamacpp_url / llamacpp_model / llamacpp_ctx (8192)
  • ollama_url / ollama_num_ctx (8192) / ollama_keep_alive / ollama_model
  • provider_configs.{id} — per-provider base_url / api_key (masked) / model / max_tokens
  • openai_base_url / openai_api_key (legacy fallbacks)

Context budget & llama-server restart

CHEGE_LLAMACPP_CTX=8192
CHEGE_DEFAULT_CONTEXT_WINDOW=8192

Keep the two context knobs distinct: CHEGE_DEFAULT_CONTEXT_WINDOW / default_context_window (8192) is the agent-side prompt budget, while CHEGE_LLAMACPP_CTX / llamacpp_ctx (8192) is the llama-server context (n_ctx). The builder subtracts tool-schema tokens and a completion reserve before adding history, so prompts stay within the server's context.

The shipped llama-server was restarted with bash scripts/llamacpp.sh restart and now listens with ctx=8192, ngl=0. Re-run that command after changing llamacpp_ctx, llamacpp_model, host/port or n_gpu_layers — a container restart alone does not apply them.

If a long thread still exceeds the budget, start a new thread or fork from a safe message to shorten the history.

Remote access & native development

There is no in-app login by design. To use the agent from another machine, keep the loopback binding and open an SSH tunnel:

ssh -N -L 8001:127.0.0.1:8001 user@your-instance
# then browse http://127.0.0.1:8001/ on your laptop

For native development, run the API on the loopback interface with uvicorn backend.app.main:app --host 127.0.0.1 --port 8001 --reload. Health checks are /healthz and /readyz; the API docs live at /docs and the OpenAPI JSON at /api/v1/openapi.json.
