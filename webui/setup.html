Setup & configuration

One command on a fresh instance; sane defaults for a personal app.

Looking to change defaults? Use the Settings console for providers, sandbox, agent limits and theme. This page is the deployment guide and .env reference.

Deploy

git clone <your-repo-url> && cd "Chege Agent"
bash scripts/deploy.sh                 # DEFAULT: Docker + llama.cpp precompiled + SQLite
bash scripts/deploy.sh --with-postgres # internal Postgres container
bash scripts/deploy.sh --with-ollama   # switch provider to host Ollama on :11434
bash scripts/deploy.sh --isolated      # separate stack; never touches existing containers
bash scripts/deploy.sh doctor          # preflight diagnostics
bash scripts/deploy.sh logs chege-agent

The script syncs .env, validates compose, builds, waits for health, and prints loopback URLs plus SSH-tunnel instructions. It never publishes the API to 0.0.0.0.

Other Docker stacks already running? Set CHEGE_PORT to a free port in .env and use --isolated: unique container names and a private network, with no orphan removal of existing apps.

Key settings (.env)

VariableDefaultPurpose
CHEGE_HOST127.0.0.1Loopback binding. Keep it.
CHEGE_PORT8000Host port.
CHEGE_SANDBOX_BACKENDdockerdocker or local (explicit opt-in).
CHEGE_DATABASE_URLemptyEmpty = SQLite; set by the Postgres overlay.
POSTGRES_PASSWORDgeneratedInternal DB password, stored only in .env.
CHEGE_DEFAULT_PROVIDERllama_cppllama_cpp, ollama or openai.
CHEGE_LLAMACPP_URL:8080/v1Host llama.cpp endpoint.
CHEGE_OLLAMA_URL:11434Host Ollama endpoint.

Providers

llama.cpp (default): run a local server on port 8080 and point CHEGE_LLAMACPP_URL at http://host.docker.internal:8080/v1.

Ollama: ollama serve on the host; URL http://host.docker.internal:11434.

OpenAI-compatible: set CHEGE_OPENAI_BASE_URL and CHEGE_OPENAI_API_KEY.

Switch providers live from the playground or with PUT /api/v1/providers/active.

Database choices

SQLite (default) is an embedded file at data/chege.db — zero ops, ideal for one person. Back it up by stopping the stack and copying the data/ directory.

Postgres runs as an internal container with a named volume and a healthcheck; port 5432 is never published. Back it up with docker compose exec postgres pg_dump -U chege chege > backup.sql (add both compose files when using the overlay).

Remote access & native development

There is no in-app authentication. To use the agent from another machine, keep the loopback binding and open an SSH tunnel:

ssh -N -L 8000:127.0.0.1:8000 user@your-instance
# then browse http://127.0.0.1:8000/ on your laptop

For native development without Docker, use CHEGE_SANDBOX_BACKEND=local and uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload. The API docs live at /docs and the OpenAPI JSON at /api/v1/openapi.json.
