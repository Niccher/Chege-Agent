Safety model

What protects your host, and what is your responsibility.

No authentication, by design. Chege Agent is a single-user local service. Anyone who can reach port 8000 has full API access, including full_auto tool execution. Keep the loopback binding and use an SSH tunnel for remote access.

Layers of protection

Network boundary

Compose publishes 127.0.0.1:8000:8000 only; Postgres has no host port at all.

Path containment

Every file target is canonicalised and rejected if it escapes workdir/{project} (traversal, symlinks, absolute paths, NUL bytes).

Approval gates

auto_edit permits ordinary writes and an exact allowlist of shell-free commands (pytest, git status, …). Deletes, commits, process kills, network and other shell commands require confirmation.

Sandbox backend

The Docker backend is intended to use the restricted socket proxy (tecnativa/docker-socket-proxy) and a per-project container. If you run with --local-sandbox, there is no process isolation — treat the agent as trusted code.

Automatic checkpoints

Each run snapshots the workspace first; revert saves dirty work to a safety stash before restoring, so unrelated edits are not lost.

Operator checklist: keep CHEGE_HOST=127.0.0.1; don't forward port 8000 through a public reverse proxy without adding your own authentication; review approval prompts; back up data/ (SQLite) or pg_dump (Postgres).
